SIMPLER CORPORATE GATEWAY INSTALLATION

Use the NEW ZIP and a new setup folder. Do not reuse yesterday's generated
ready JSON: it contains the old embedded installer.

1. Check yesterday's stack cleanup before launching another stack. Delete only
   your project's leftover resources. The versioned S3 bucket may be retained.
2. Start Learner Lab and open AWS in us-east-1 (N. Virginia).
3. Open CloudShell and upload Corporate_Gateway_Quick_Install.zip using Actions.
4. Run:

   mkdir -p gateway-simple
   unzip -q Corporate_Gateway_Quick_Install.zip -d gateway-simple
   cd gateway-simple/gateway_deployment
   python3 tools/prepare_lab.py

5. Download gateway-stack-ready.json using Actions > Download file and the full
   path printed by the helper. Upload that JSON in CloudFormation > Create stack.
6. Enter your AlertEmail. Keep the prefilled role/profile/certificate defaults.
   Leave ApplicationHostname blank. Leave the optional CloudFormation service
   role blank on the later Permissions page. Keep normal rollback enabled.
7. Wait for the WHOLE STACK to show CREATE_COMPLETE. Outputs > ApplicationURL
   opens the portal. Outputs > ApplicationSecretArn identifies the portal login
   secret in Secrets Manager. Retrieve its username/password privately.
8. Confirm the SNS subscription email before testing the alarm.

No domain purchase or new IAM role is required for the self-signed lab route.
The test certificate causes browser warnings; use dummy files and disclose this
limitation. Trusted public HTTPS still requires a matching trusted certificate.
If CloudShell, existing-profile reads or ACM import are denied, keep the exact
error; do not modify LabRole or substitute personal AWS credentials.

WHAT WAS SIMPLIFIED
The serving tier now has one application service per server, directly serving
HTTPS on private port 8443. Nginx and the CloudWatch log-agent installation have
been removed. ALB/RDS/EC2 service metrics, the dashboard, alarms and SNS remain.
Two private app servers, two AZs, S3 and Multi-AZ PostgreSQL are retained because
these are part of the required architecture. Application source is inside JSON.
Local app logs remain on each server; they are not shipped to CloudWatch Logs.

IF AN INSTANCE FAILS
"Received FAILURE signal with UniqueId i-..." means bootstrap ran and exited
non-zero. Copy the FULL Status reason from Events (look for stage: ...). If the
instance still exists, Session Manager:

   sudo cat /var/log/gateway-setup-stage
   sudo cat /var/log/gateway-setup-error
   sudo tail -n 200 /var/log/gateway-setup-detail
   sudo tail -n 100 /var/log/cloud-init-output.log
   sudo journalctl -u gateway -n 60 --no-pager

Do not share credentials or secret values. Wait for rollback to finish before
redeploying. See START_HERE.txt for stage-to-cause mapping.

REPORT CHANGES
Describe ALB to Flask HTTPS on port 8443, with no Nginx layer. CloudWatch uses
AWS service metrics; application logs are local. Do not claim centrally shipped
application logs. The existing broad lab role and self-signed certificate
limitations remain. Collect real AWS results before making success claims.
